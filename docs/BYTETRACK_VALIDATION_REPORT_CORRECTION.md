# ByteTrack Validation --- Short-Track Check Correction

## Purpose

This change fixes a contradiction in the ByteTrack validation report.
The earlier report said that no very short tracks were present while
also reporting four tracks below the check's threshold.

The validation rule and its reported message now use one consistent
definition.

## Definition used

A track is classified as **very short** when it has **fewer than 5
observed frames**.

The count is computed from the number of unique observed frame numbers
for each `track_id`, rather than the track's frame-span length. A track
with four observed frames is therefore very short; a track with five
observed frames is not.

## Logic change

The validation script calculates the count using the same threshold for
the hard check and the displayed statistics:

``` python
SHORT_TRACK_THRESHOLD = 5

short_tracks = int(
    (track_summary["observed_frames"] < SHORT_TRACK_THRESHOLD).sum()
)

check(
    short_tracks == 0,
    (
        "No very short tracks "
        f"(fewer than {SHORT_TRACK_THRESHOLD} observed frames); "
        f"found {short_tracks}"
    ),
)
```

The summary output and text report should use the same
`SHORT_TRACK_THRESHOLD` value. This avoids having separate thresholds or
contradictory wording in different parts of the report.

## Results in the regenerated report

The corrected report generated from the supplied baseline tracking data
records:

  Metric                                       Result
  ------------------------------------------ --------
  Input detections                              5,598
  Tracked output rows                           3,518
  Output/input ratio                           62.84%
  Input frames                                    280
  Tracked frames                                  280
  Unique track IDs                                 77
  Duplicate frame/ID rows                           0
  Tracks with fewer than 5 observed frames         12
  Failed hard checks                                1

The short-track check remains a failed quality check because 12 tracks
meet the defined short-track condition. The report should preserve this
result rather than hiding or downgrading it just to make validation
appear successful.

The count differs from the earlier four because the earlier check used
fewer than 3 observed frames. The corrected threshold also includes
tracks with 3 or 4 observed frames.

## Interpretation

This correction fixes report consistency; it does not improve tracking
quality by itself. The 12 short tracks remain a tracking-quality
observation that may warrant review. Structural validation and visual
identity continuity are separate: passing other checks does not prove
that each person retains the correct identity across the video.
